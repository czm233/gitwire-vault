## 修复

- **guardrails 在 Python 3.11+ 导入失败**：`BaseGuardrail` 继承 `Middleware` 时显式传入 constraint 参数 `Middleware[_P, _R, _MiddlewareSignature[_P, _R]]`，绑定本模块的 `_P`/`_R`（`packages/railtracks/src/railtracks/guardrails/core/interfaces.py`，`75c3b17` / #1591）。背景：`Middleware` 泛型在 2f1626e 新增第三参数（constraint），Python 3.11+ 下隐式继承推断失败导致导入报错。
- 配套文档与测试：`test_middleware_values_match` 更新 middleware 技能描述断言（`packages/railtracks/tests/unit_tests/cli/skillkit/test_registry.py`，`4726cf2`）。

## 重构

- **agent-facing 文档全面改写（#1583，`4726cf2`）**：AGENTS.md 与 bundled skills 改为面向 coding agent 消费——压缩叙述、去除过程性口吻（如「必须完成才算改完」类指导语）、把「阻塞式预览」与「验证步骤」区分（`mkdocs serve` 标注为 blocking 非 verification，验证以 `mkdocs build --strict` 为准）（AGENTS.md、`.claude/skills/code-style/SKILL.md`）。
- 技能描述收敛为可机读的行动指引：middleware 技能 description 改为「Add middleware to a railtracks agent or node (retries, logging, timing, guardrails, context injection)…」（`cli/skills/middleware/SKILL.md`）；agent-builder 技能中「类型自动选择」表述改为「行为取决于传入 tools/schema」（`cli/skills/agent-builder/SKILL.md`）。

## 知识性变更（影响档案判断）

- **rag-pipeline 技能新增 embedder 选择规则**：已有 collection 必须沿用建库时的 embedder/模型（混用会抛 `EmbeddingModelMismatchError`），否则按项目既有 provider 或已配置的 API key 选择，仍不确定则询问用户；本地离线用 `OllamaEmbedding`（`cli/skills/rag-pipeline/SKILL.md`，`4726cf2`）。
