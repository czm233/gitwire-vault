# Changelog — 2026-09-25（`75c3b17` → `ee5d84d`）

结论：本次为单一特性提交——在 LLM 响应层全链路透出模型 reasoning/thinking（#1431/#1563），覆盖非流式、流式、结构化输出、工具调用循环与序列化，并保证签名 thinking blocks 在 Anthropic 回传语义下不丢失。

## 新增

- `AssistantMessage` 新增 `reasoning_content`（纯文本）与 `thinking_blocks`（带签名的结构化块）元数据属性；新增 `copy_metadata_from()` 用于重建路径无损搬运元数据，`encode()` 将两者写入序列化消息，随运行图/会话数据可见（packages/railtracks/src/railtracks/llm/message.py，ee5d84d）。
- `Response` 新增 `reasoning` 只读属性，作为 `message.reasoning_content` 的便捷访问，无推理时为 None（packages/railtracks/src/railtracks/llm/response.py）。
- litellm wrapper：新增 `_attach_reasoning`（把 litellm message/delta 上的推理字段贴到 AssistantMessage）与 `_echo_reasoning`（每轮 assistant 消息均回传 reasoning/thinking_blocks，Anthropic 要求签名块回传以保持 thinking turn 有效）；流式路径累积 `reasoning_content`，并保留原始 chunks 交由 litellm 的 `_assemble_thinking_blocks` 重组签名块（仅当流中出现过 thinking blocks 才执行）（packages/railtracks/src/railtracks/llm/models/_litellm_wrapper.py）。
- 新增日志器 `logging.getLogger("RT.litellm_wrapper")`，挂在 RT 日志树下且不向上依赖 railtracks.utils（同文件）。
- 文档新增「Accessing the reasoning a model returned」一节：示例展示 `response.reasoning` / `response.message.reasoning_content` / `response.message.thinking_blocks` 三种读取方式，说明推理随消息入 history 与序列化；流式时推理累积后挂在最终 `Response` 上，不作为独立 stream chunk 发出（docs/documentation/agent_design/llms/common_hyperparams.md）。

## 修复

- 工具调用循环重建历史消息时丢失 provider 元数据的问题：`llm_invoke` 的 Content/Structured 分支与 `run_tools` 均改为 `AssistantMessage(...).copy_metadata_from(response.message)`，既保留 reasoning/签名 thinking blocks/raw litellm message，又保证 history 与 `post_llm` 中间件可能仍会修改的 Response 对象相互隔离（packages/railtracks/src/railtracks/built_nodes/llm/llm_helpers.py，ee5d84d）。

## 重构

- `run_tools` 中手工搬运 `raw_litellm_message` 的逻辑并入统一的 `copy_metadata_from`（llm_helpers.py）。
