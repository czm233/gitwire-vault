# Railtracks v1.5.5 情报简报

**BLUF**：v1.5.5（2026-09-30）是一个混合版本，既包含 schema/retrieval/middleware 多处行为修复与一次破坏性的公共 API 收缩（移除 `rt.Session`），也新增了 Skills 目录支持、ConversationMemory 中间件、思考 token 暴露等功能，升级需重点核对依赖 pin 和 `rt.Session` 用法。

## 升级建议
- **破坏性**：PR #1575 将 `rt.Session` 从公共表面与错误提示中移除，凡直接引用 `rt.Session` 的代码需迁移（替代 API 未在 notes 说明，未核实）。
- **依赖变更**：litellm pin 收紧为 `>=1.101.0,<=1.102.1`（#1600，为 gpt-6 reasoning_effort）；anyio 升至 4.15.1（#1597）。若你的环境锁了这些依赖需同步调整。
- **行为变化**：schema 对未识别的参数类型现在直接拒绝而非默认为 object（#1552），依赖宽松类型推断的代码可能开始报错。
- retrieval 的 staleness 检查与 delete-before-write 改为按租户隔离（#1565），多租户场景下行为更安全但结果可能与旧版不同。
- Python 3.11+ 的 guardrails 导入修复（#1591）依赖 Middleware constraint 参数 pin，3.11+ 用户务必升级到此版本。

## 变更明细
- **修复**
  - schema：拒绝未识别参数类型，不再默认 object（#1552）
  - retrieval：staleness 检查与 delete-before-write 按租户隔离（#1565）
  - history：保留调用方 system messages 在返回历史中（#1564）
  - middleware：视为共享实例，MaxCalls 与 Lock 在 node 槽位生效（#1561，backport #1560）
  - 成本显示：定价查询失败时渲染 unknown 而非 $0.00（#1568）
  - guardrails：pin Middleware constraint 参数，恢复 Python 3.11+ 导入（#1591）
  - 保留 function node 中间件类型推断（#1558）
  - CLI：Windows 路径分隔符测试修复（#1586）
- **功能**
  - CLI：支持安装所有 bundled skills（#1540）；Skills 基础设施支持目录（#1483）
  - retrieval：新增结构化内容提取器（#1543）
  - prebuilt：新增 ConversationMemory 中间件并规范 prebuilt 文档（#1571）
  - LLM 响应中暴露 thinking token（#1563）
  - verifier 事件发射 + viz 分类（#1569）
  - context events 纳入（#1601）
- **其他**：args 解析改进（支持描述换行与冒号，#1494）；flows 测试补充（#1567）；大量文档更新（定位为 agent harness 框架 #1559、AGENTS.md 面向 agent #1583 等）。
